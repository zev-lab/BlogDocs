# Go 语言数据结构与底层实现

Go 语言提供了一系列丰富的内置数据类型，分为值类型和引用类型。理解这些数据类型的底层实现，是写出高性能 Go 代码的关键。

## 1. 内置类型概览

### 值类型
值类型在赋值或作为参数传递时，会进行内存拷贝。
- **布尔型**: `bool`
- **整型**: `int(32/64)`, `int8`, `int16`, `int32`, `int64`, `uint`, `byte`, `rune`
- **浮点型**: `float32`, `float64`
- **复数**: `complex64`, `complex128`
- **字符串**: `string`
- **数组**: `array` (固定长度)
- **结构体**: `struct`

### 引用类型
引用类型底层通过指针实现，赋值和传参时拷贝的是指针。
- **切片**: `slice`
- **映射**: `map`
- **管道**: `chan`
- **接口**: `interface`

### 内置函数
- `make`: 用于分配内存并初始化，**仅适用于** `slice`, `map`, `chan`。
- `new`: 用于分配内存，返回类型的指针。
- `append`, `copy`: 用于操作切片。
- `len`, `cap`: 获取长度和容量。
- `panic`, `recover`: 用于异常处理。
- `delete`: 从 map 中删除元素。
- `close`: 关闭 channel。

## 2. 数组 (Array)

::: warning 注意
数组和切片是 Go 语言中容易混淆的概念。数组是固定长度的，而切片是动态的。了解它们的底层区别，对于避免常见的性能陷阱至关重要。
:::

数组是由相同类型元素的集合组成的数据结构，计算机会为数组分配一块连续的内存来保存其中的元素。我们可以利用数组的索引快速访问特定元素。

### 初始化
```go
// 声明并初始化
var arr1 [5]int = [5]int{1, 2, 3, 4, 5}
// 编译器推导长度
arr2 := [...]int{1, 2, 3}
```

Go 语言中的数组类型由**元素类型**和**数组长度**共同决定。`[3]int` 和 `[4]int` 是完全不同的两种类型，无法直接比较或相互赋值。

数组在函数参数传递时是**值传递**，会导致整个数组的复制，因此在处理大数组时，通常建议传递切片或数组指针。

## 3. 切片 (Slice)

切片是 Go 语言中最常用的数据结构之一，它在数组的基础上提供了一种灵活、方便且强大的接口。切片本身并不存储任何数据，它只是对底层数组的一个引用（视图）。

### 底层结构
在 Go 的运行时 `reflect.SliceHeader` 中，切片的结构如下：
```go
type SliceHeader struct {
    Data uintptr // 指向底层数组的指针
    Len  int     // 切片当前包含的元素个数
    Cap  int     // 底层数组的容量
}
```

### 扩容机制
当我们使用 `append` 函数向切片追加元素且容量不足时，切片会触发扩容：
1. Go 1.18 之前：如果原切片容量小于 1024，新容量翻倍；如果大于等于 1024，新容量增加 1/4。
2. Go 1.18 之后：为了更平滑的扩容曲线，采用了新的计算公式，但总体原则依然是小容量时翻倍，大容量时平缓增长。

扩容会导致分配新的底层数组，并将原数据拷贝过去。因此，如果能预估数据量，使用 `make([]T, len, cap)` 预先分配好容量，能有效提升性能。

## 4. 哈希表 (Map)

Go 语言中的 `map` 是一个无序的键值对集合，底层基于**散列表（哈希表）**实现。

### 底层结构
`map` 的底层是一个 `hmap` 结构体：
```go
type hmap struct {
    count     int // 元素个数
    flags     uint8
    B         uint8  // buckets 数组长度的对数，即 len(buckets) == 2^B
    noverflow uint16 // 溢出桶的大概数量
    hash0     uint32 // hash 种子
    buckets    unsafe.Pointer // 桶数组的指针
    oldbuckets unsafe.Pointer // 扩容时，保存旧桶数组的指针
    // ...
}
```

每个 `bucket` (底层称为 `bmap`) 可以存储 8 个键值对。当发生哈希冲突时，Go 会将冲突的元素放入同一个桶中。如果桶满了，会通过链表指针连接一个“溢出桶”（overflow bucket）。

### 扩容机制
当 `map` 的负载因子（count / 2^B）超过 6.5，或者溢出桶数量过多时，会触发**渐进式扩容**。扩容时不会一次性将所有数据迁移，而是在每次插入、修改或删除操作时，顺带搬迁一部分数据，以此来均摊性能消耗。

## 5. 字符串 (String)

Go 语言中的字符串是一个不可变的字节序列（通常是 UTF-8 编码）。

### 底层结构
字符串的底层结构 `StringHeader` 如下：
```go
type StringHeader struct {
    Data uintptr // 指向底层字节数组的指针
    Len  int     // 字符串的字节长度
}
```

### 特性
1. **不可变性**：字符串一旦创建，其底层字节数组就无法修改。如果尝试 `str[0] = 'a'` 会导致编译错误。
2. **高效切片**：对字符串进行切片操作（如 `str[1:3]`）非常高效，因为它们共享同一个底层的字节数组，只会创建一个新的 `StringHeader`。
3. **字符串与字节切片转换**：`[]byte(str)` 和 `string(bytes)` 会导致内存分配和数据拷贝。在性能敏感场景下，可以使用 `unsafe` 包进行零拷贝转换（需谨慎）。
