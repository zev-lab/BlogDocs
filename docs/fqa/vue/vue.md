# Vue 常见问题与解答 (FAQ)

在使用 Vue.js 开发过程中，经常会遇到一些常见的问题和坑。本文总结了一些常见的 Vue 问题及其解决方案和最佳实践。

## 1. Vue 响应式原理是什么？

Vue 的响应式系统在 Vue 2 和 Vue 3 中有所不同：

- **Vue 2**：使用 `Object.defineProperty` 遍历对象的所有 property，并利用 getter/setter 拦截对属性的访问和修改。结合发布订阅模式（Dep 和 Watcher）实现响应式。**缺点**：无法检测对象属性的添加或删除；无法监听数组索引和长度的变化（Vue 内部通过重写数组方法进行 hack 解决）。
- **Vue 3**：使用 ES6 的 `Proxy` 来代理整个对象。它可以完美监听到对象属性的新增和删除，以及数组索引和长度的变化。性能更好，也原生支持了 Map、Set 等数据结构。

## 2. 为什么组件中的 `data` 必须是一个函数？

如果 `data` 是一个对象，那么在复用组件时，所有的实例将共享这同一个数据对象，导致一处修改，处处变化。
当 `data` 是一个函数时，每次复用组件都会调用这个函数返回一个新的对象，从而保证每个组件实例都有自己独立的数据作用域，互不干扰。

## 3. `v-if` 和 `v-show` 的区别是什么？

- **`v-if`**：是真正的条件渲染。它会确保在切换过程中，条件块内的事件监听器和子组件适当地被销毁和重建。如果初始渲染时条件为假，则什么也不做。
- **`v-show`**：不管初始条件是什么，元素总是会被渲染，并且只是简单地基于 CSS 的 `display` 属性进行切换。

**最佳实践**：如果需要非常频繁地切换，使用 `v-show` 较好；如果在运行时条件很少改变，则使用 `v-if` 较好。

## 4. `v-for` 中为什么要用 `key`？

`key` 的特殊属性主要用在 Vue 的虚拟 DOM 算法，在新旧 nodes 对比时辨识 VNodes。

如果不使用 `key`，Vue 会使用一种最大限度减少动态元素并且尽可能的尝试就地修改/复用相同类型元素的算法。
而使用 `key` 时，它会基于 key 的变化重新排列元素顺序，并且会移除/销毁 key 不存在的元素。使用唯一标识（如 id）作为 key，可以提升渲染性能和避免一些状态混乱的问题（如 input 输入框的内容错位）。

## 5. `computed` 和 `watch` 的区别？

- **`computed`（计算属性）**：
  - 依赖于其他属性计算而来，具有缓存特性。
  - 只有当其依赖的响应式数据发生变化时，才会重新计算。
  - 必须有返回值。
  - 适用于多个值影响一个值，且需要格式化输出的场景。

- **`watch`（侦听器）**：
  - 监听特定的响应式数据，当数据变化时执行回调函数。
  - 无缓存特性。
  - 适用于一个数据变化需要引发一连串操作或异步操作的场景。

## 6. Vue 组件间通信方式有哪些？

1. **父传子**：使用 `props`
2. **子传父**：使用 `$emit` 触发自定义事件
3. **兄弟组件**：通过共同的父组件（状态提升），或使用 EventBus（Vue 2），或借助全局状态管理（如 Vuex / Pinia）。
4. **跨级组件**：
   - `provide` / `inject`
   - Vuex / Pinia
5. **获取组件实例**：使用 `ref` 获取子组件实例进行方法调用或属性访问。

## 7. 如何解决 Vue Router 的路由 history 模式下刷新 404 的问题？

在 history 模式下，URL 改变时浏览器会向服务器发送请求。因为我们是单页应用（SPA），只有 `index.html` 一个入口文件。如果直接访问如 `/user/profile` 的路径，服务器上并没有这个资源，所以会返回 404。

**解决办法**：在服务器端进行配置，将所有未匹配到的路由请求都重定向到 `index.html`。

例如 Nginx 配置：
```nginx
location / {
  try_files $uri $uri/ /index.html;
}
```

## 8. Vue 中的 nextTick 是什么？

`nextTick` 是 Vue 提供的一个全局 API。它的作用是在下次 DOM 更新循环结束之后执行延迟回调。
在修改数据之后立即使用这个方法，获取更新后的 DOM。

```javascript
this.message = 'updated'
this.$nextTick(() => {
  // 这里的 DOM 已经更新了
  console.log(this.$el.textContent)
})
```
